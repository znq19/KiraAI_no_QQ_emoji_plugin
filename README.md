# 禁止QQ Emoji

还在为哪怕人设提示词里写了禁止发送 emoji，自己的 bot 还在频繁发送 QQ 黄豆表情、显得非常人机而让你想 😓 吗？那么快安装本插件吧。

> **注意**：本插件只负责不让 bot 发 **QQ emoji**，而非所有的 emoji。
> 后者在我看来偶尔作为表达方式还是不错的，且人设提示词里可以较好抑制。
> 主要原因是前者在 bot 眼里被 KiraAI 框架注册成了一个独立标签（`<emoji>`），
> 看起来更像「表情包」而不是通常意义上的 emoji，所以提示词约束往往压不住它。

## 它做什么

在每轮 LLM 请求时，从输出的标签表中移除 `<emoji>` 标签。
模型看不到这个标签，自然就不会再输出 QQ 黄豆表情。

## 它不做什么

| 能力 | 是否受影响 |
|---|---|
| 发送表情包（sticker） | ❌ 不受影响 |
| 戳一戳 / @ / 图片 / 语音 / 文件 / 转发 | ❌ 不受影响 |
| 识别用户发来的 QQ emoji | ❌ 不受影响 |
| 识别用户发来的贴表情 | ❌ 不受影响 |
| 模型直接输出 Unicode 表情（😀🥺） | ⚠️ 仍可输出，本插件不管这个 |

## 生效范围

本插件作用于 `<emoji>` **这个标签**，而不是某个平台。
因此凡是在 KiraAI 中声明了 `emoji` 能力的适配器都会生效：

| 适配器 | 是否声明 emoji | 本插件是否生效 |
|---|---|---|
| QQ | 是 | ✅ |
| QQ 官方机器人 | 是 | ✅ |
| Telegram | 是 | ✅ |
| Discord | 是 | ✅ |
| BiliBili | 是 | ✅ |
| 微信个人号 / WebChat | 否 | — 无 emoji 标签，天然无影响 |

如果你同时接了多个平台、且只希望在 QQ 上禁止，直接停用本插件即可（或自行加一行平台判断）。

## 边界情况

- **模型偶尔仍执意输出 `<emoji>`**：框架 `parse_xml` 只处理标签表里存在的标签，
  未注册的标签会被**静默丢弃**，不报错、不崩。
  若某条 `<msg>` 里只剩表情，该条不会发送（不会发出空消息）。
- **其它插件用 `@register.tag("emoji", ...)` 注册了持久标签**：这类标签在本插件的钩子
  之后才被写入标签表，可能被重新加回。内置插件没有这种用法，仅当第三方插件主动提供
  emoji 标签时才会出现。

## 安装

1. 下载本仓库，把 `KiraAI_no_QQ_emoji_plugin/` 整个目录放进 KiraAI 的 `data/plugins/` 下
   （或在 WebUI 插件页直接填仓库地址 `znq19/KiraAI_no_QQ_emoji_plugin` 一键安装）
2. 重启 KiraAI（或从 WebUI 插件页重新加载）
3. 确认插件列表中「禁止QQ Emoji」为已启用

> **从 1.0.0 升级**：旧版会把 `emoji` 从适配器的能力声明里永久删掉，
> **请先重启一次 KiraAI 恢复**，再替换为本版本，否则 emoji 会一直缺失。

## 配置

只有一项：`enabled`（默认开启）。切换后**即时生效，无需重启**。

注意这与插件卡片上的启用开关是两回事：卡片开关会卸载插件，`enabled` 只是让钩子直接跳过。

## 兼容性

- 需要 KiraAI `>= 3.0.0`（已在 3.0.0 / 3.0.1 / 3.1.2 / 3.2.0-beta.1 上实测通过）
- 基于 `@on.llm_request` + `TagSet` 实现，不修改任何全局状态
- 停用插件后 emoji 立即恢复，不存在不可逆的副作用

## 实现说明

```python
@on.llm_request(priority=Priority.MEDIUM)
async def strip_emoji_tag(self, event, _request, tag_set):
    tag_set.unregister("emoji")
```

`TagSet` 每轮请求新建，因此该操作天然幂等、完全可逆；
钩子按优先级降序执行，`MEDIUM < SYS_HIGH`，保证在内置插件注册 emoji 标签之后、
格式提示词渲染之前完成摘除。

每轮开销为一次标签名扫描（≤11 个元素，实测约 355 ns），无 I/O、无锁、无 await。
